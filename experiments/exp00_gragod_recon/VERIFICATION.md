## [의혹 1] models/gdn/model.py:271, 304 의 reshape가 전치와 다른가

**판정: 참**

의미: `GDN_PLModule`이 `(batch, window, feature)` 배치를 `(batch, feature, window)`로 바꿀 때 permute(전치)가 아니라 reshape(메모리 재해석)를 쓴다. 그래서 모델이 "채널 j의 시계열"로 읽는 행이 실제 채널 j의 값들이 아니다. 비정방(window≠feature)에서는 시점·채널이 뒤섞인 값이 되고, 정방(window=feature)에서는 reshape가 항등이라 "시점 j의 채널별 값"이 채널 j의 시계열 자리에 들어간다. 어느 쪽이든 원소 단위로 permute와 어긋난다.

실행 출력 (그대로):

```text

원본 windows shape: (2, 4, 4)  (batch, window, feature)
```

## [의혹 2] gragod/predictions/prediction.py 의 smooth_scores 가 어느 축에 작용하는가

**판정: 참** (feature 축에 작용한다 — 시간 축이 아님)

의미: `smooth_scores`가 `(n_samples, n_features)` 2D 텐서를 받으면 `F.pad`/`avg_pool1d`가 마지막 축, 곧 feature 축에 걸린다. 근거 숫자는 셋이다. 상수 채널1(전부 100)이 20으로 변형됐다 — 시간 축 이동평균이라면 상수 열은 어떤 창에서도 100 그대로여야 한다. 출력 행 [0, 20, 60]은 feature 축 5-창 평균의 손계산 값과 정확히 일치한다. t=5의 뾰족값은 시간축 이웃 t=6..9로 전혀 퍼지지 않았다(해당 시점들 출력 60 그대로). GDN 예측 경로(`models/predict.py:66-68` → `post_process_scores` → `smooth_scores`)의 "smoothing"은 시간축 평활이 아니라 채널 방향 혼합이라는 뜻이다.

사용자 요청에 따른 부기 — 시간축 평활을 의도할 경우의 올바른 호출 형태(GraGOD 코드 무수정, 호출부에서 전치): `smooth_scores(scores.T, window_size).T`. 이 형태가 채널 독립을 유지하며 뾰족값만 시간축으로 퍼뜨린다는 것(후행 5-창, replicate 패딩)을 아래 출력 마지막 블록에서 수치로 확인했다.

실행 출력 (그대로):
