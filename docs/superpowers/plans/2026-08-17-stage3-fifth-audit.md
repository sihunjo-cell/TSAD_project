# 3단계 5차 논리 감사 실행 계획

> 현재 누적 작업공간에서 수행한다. 기존 변경을 커밋하지 않으며 실제 GHL·HAI 학습, 합성 모델 실행, 원본 CSV 재검증은 하지 않는다.

**목표:** D-34~D-41의 확정값을 다시 고르지 않고, 장시간 배치의 마지막 미검사 경계인 “입력 검증 뒤 실제 로드까지 파일이 같은가”를 닫은 뒤 3단계 정적 감사의 종료 조건을 고정한다.

## 순환 여부 판정

- D-34에서 점수 길이를 `L-W-1`에서 `L-W`로 한 번 고친 뒤 다시 되돌린 기록은 없다.
- 비율, seed, validation 0.1, window 5, GHL·HAI topk 5·22는 1~4차 감사에서 바뀌지 않았다.
- 2~4차 수정은 실패·완료 판정, 실행 신원, 파생 로그처럼 서로 다른 계층을 보강했다. 같은 결정을 순환해서 고친 것은 아니다.
- 다만 감사마다 새 계층을 열어 본 탓에 종료 범위가 흐려졌다. 이번 감사 뒤에는 입력·분할·러너·완료 판정·파생 산출물의 정적 검사를 닫는다.

## 감사 순서

1. D-34~D-41과 관련 코드·테스트를 대조해 확정값의 번복 여부를 확인한다.
2. 입력 manifest의 SHA-256 검증과 실제 로드 사이에 외부 파일이 바뀌는 경우를 실패 테스트로 재현한다.
3. 시작 시 SHA-256은 한 번만 계산하고, 각 로드 직전·직후에는 크기와 수정 시각만 확인하는 최소 방어를 넣는다.
4. GHL 주 배치, GHL 대조군, HAI 배치가 모두 모델 실행 전에 변경을 거부하는지 확인한다.
5. 관련 테스트와 고정 환경 전체 단위 테스트, YAML, 환경 계약, compile, diff를 한 번씩 검증한다.

## 종료 기준

- 이번에 재현한 결함과 회귀 테스트가 모두 닫히면 3단계 5차 감사를 끝낸다.
- 이후 코드·설정·데이터·외부 근거가 바뀌지 않은 상태에서 같은 정적 감사를 요청받아도 읽기 전용 대조만 한다. 새 재현 사례가 없으면 코드와 결정을 수정하지 않는다.
- 3단계를 다시 여는 조건은 새 diff, manifest 불일치, 외부 레포 고정본 변경, 실패 테스트, 실제 dryrun 실패뿐이다.
- 다음 실행 작업은 별도 승인된 commit·clean 상태에서 합성 dryrun을 다시 만드는 절차다. 4단계는 계속 닫아 둔다.

## 수행 결과

- D-34~D-41을 대조했다. 점수 길이는 D-34에서 한 번 교정됐고, 비율·seed·validation·window·topk는 한 번도 되돌리지 않았다. 1~4차 수정은 서로 다른 실행 계층을 보강했으므로 순환 수정은 아니었다.
- 입력 manifest를 한 번 검증한 뒤 장시간 배치가 다른 시점에 파일을 다시 읽는 공백을 재현했다. 기존 코드는 로드 중 파일이 바뀌어도 세 배치 모두 모델을 호출했다.
- 최초 SHA-256 전후의 크기·`mtime_ns`를 묶어 지문에 남기고, GHL 주 배치·대조군과 HAI가 실제 입력을 읽기 직전·직후 같은 상태인지 확인하도록 고쳤다. 로드마다 SHA-256을 반복하지 않는다.
- 실패 테스트 네 건을 먼저 확인한 뒤 관련 테스트 25건과 고정 `tsad_fixed` 환경 전체 단위 테스트 104건을 통과했다. YAML 5개, 환경 12항목, 실험 조합 `375·225·150·450·20`, compileall, `git diff --check`도 통과했다.
- 고정 GraGOD 포크는 HEAD `485e26b0c6b1d63f4f3531c8d05597db82e9db29`, clean 상태였다. 실제 모델, 합성 dryrun, 원본 CSV·SHA-256 재검사, commit은 수행하지 않았다.
