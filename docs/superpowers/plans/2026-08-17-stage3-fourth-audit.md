# 3단계 4차 논리 감사 실행 계획

> 현재 누적 작업공간에서 직접 수행한다. 기존 변경을 옮기거나 커밋하지 않으며, 실제 GHL·HAI 학습과 합성 모델 실행은 하지 않는다.

**Goal:** 3차 감사까지 확정한 계약을 보존하면서 수치 경계 계산, 설정 간 불변식, 파생 산출물 신원에서 실제 결과를 바꾸는 남은 결함을 찾고 닫는다.

**Architecture:** 3a 봉인 로그와 YAML을 원천으로 삼아 각 수치의 계산·소비 경로를 정적으로 추적한다. 결함은 현재 설정이나 허용 입력에서 재현할 수 있을 때만 실패 테스트로 고정한 뒤 원인 지점 하나를 최소 수정한다.

**Tech Stack:** Python 표준 라이브러리, PyYAML, NumPy, 기존 `unittest` 모음.

---

## 범위와 금지선

- 기준선은 `AGENTS.md`, `docs/NEXT_SESSION_PLAN.md`, `DECISIONS.md` D-01~D-40, 앞선 세 감사 기록이다.
- 3a의 원본 CSV를 다시 읽거나 SHA-256을 다시 계산하지 않는다. 봉인 로그와 manifest만 대조한다.
- 실제 GDN 학습, 합성 모델 학습, GHL 스모크, 전체 배치는 실행하지 않는다.
- 사용자 검토 전 커밋하지 않으며 4단계로 넘어가지 않는다.

## 감사 순서

### Task 1: 수치 경계와 설정 불변식

- front-trim, validation split, 점수·라벨 정렬의 반올림 경계를 실제 GHL·HAI 길이에서 다시 계산한다.
- 데이터셋별 채널 수·`topk`, 비율·seed, window·최소 학습 길이, 대조군 부분집합이 YAML끼리 모순 없는지 기계적으로 확인한다.
- 부동소수점이나 암묵적 기본값이 행 하나 또는 실험 조합 하나를 바꿀 수 있는지 찾는다.

### Task 2: 파생 산출물과 실행 신원

- snapshot, timing, score metadata, adjacency, `COMPLETE`, HAI Jaccard의 생성 순서와 소비 조건을 정상·중단·재개 경로로 추적한다.
- 현재 commit과 설정이 다른 산출물을 새 결과로 오인할 수 있는 경로, 실제 실행 장치처럼 해석에 필요한 출처가 빠진 경로를 점검한다.
- 자기 코드가 쓰지 않는 임의 파일 변조까지 막는 방어 코드는 추가하지 않는다.

### Task 3: 결함 수정

- 재현되는 결함마다 실패 테스트를 먼저 추가해 기대 계약을 명시한다.
- 표준 라이브러리와 기존 함수로 원인을 고치는 최소 diff만 적용한다.
- 재현 결함이 없으면 코드 변경 없이 확인 결과만 이 문서에 남긴다.

### Task 4: 검증과 기록

- 관련 테스트와 전체 단위 테스트, YAML 파싱, 환경 계약, `compileall`, 실험 수 계산, `git diff --check`를 실행한다.
- 새 모델·데이터 산출물이 생기지 않았는지 확인한다.
- 변경이 생기면 `DECISIONS.md` D-41, `docs/pre_run_checklist.md`, `docs/NEXT_SESSION_PLAN.md`를 같은 계약으로 맞춘다.

## 완료 조건

- 유지한 결정과 고친 결정을 나눠 기록한다.
- 모든 수정은 실패 테스트와 수정 후 통과 증거를 함께 갖는다.
- 완료 보고에는 끝난 단계, 설계 근거 위치, 원본 레포 경로·줄 번호, 실행하지 않은 항목을 적는다.

## 수행 결과

- 실제 kept length 23종에서 validation 10%의 float ceil과 정확 유리수 ceil은 모두 같았다. split 계산은 바꾸지 않았다. YAML의 `min_train_length=W+1`, 데이터셋별 `topk={5,22}`, 비율·seed·대조 팔 부분집합과 조합 수 `375·225·150·450·20`도 일치했다.
- GHL 625행과 HAI 40행의 feasibility 로그가 정규화 표본 수만 폐기된 `L-W-1`로 세고 있었다. 현 러너·D-34·고정 GraGOD `datasets/dataset.py:47-50,64-77`에 맞춰 두 생성식과 로그 665행을 `L-W`로 고쳤다. train·validation window 수와 feasibility 합격 판정은 바뀌지 않았다.
- `timing.json`에 실제 accelerator를 더했다. 계획서의 시간 비교에서 CPU와 CUDA의 초 단위를 같은 조건으로 오인하지 않게 했다. 고정 GraGOD `gragod/utils.py:83-92`가 반환하는 실행 장치 문자열을 그대로 기록한다.
- HAI Jaccard 쌍별·요약 CSV 각 행에 TSAD와 GraGOD commit을 넣었다. 이전 실행의 CSV가 남아 있어도 행 자체에서 신원을 판별한다.
- 세 결함은 기존 코드에서 실패하는 회귀 테스트로 먼저 확인했다. 관련 테스트 44건과 고정 `tsad_fixed` 환경 전체 단위 테스트 100건이 통과했다. YAML 5개·환경 12항목·실험 조합, `compileall`, `git diff --check`도 통과했다.
- 실제 GHL·HAI·합성 모델은 실행하지 않았다. 원본 CSV와 SHA-256을 다시 읽지 않았고 commit도 만들지 않았다. 4단계는 계속 닫혀 있다.
