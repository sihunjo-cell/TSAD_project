# 3단계 2차 논리 감사 계획

> 범위는 3a와 3b까지다. 실제 GHL·HAI 학습과 4단계 진입은 하지 않는다.

## 판정 원칙

- 1차 수정 결과를 정답으로 가정하지 않고 데이터 근거부터 실행 산출물까지 다시 잇는다.
- 현재 설정이 유효하다는 이유만으로 끝내지 않는다. 승인된 설정이 바뀌거나 모델 출력이 깨졌을 때 실행이 닫히는지도 확인한다.
- 결함이 재현될 때만 실패 테스트를 먼저 추가하고, 그 테스트를 통과시키는 최소 코드만 고친다.
- 원본 대형 CSV와 SHA-256은 다시 읽지 않는다. 이미 봉인한 manifest와 EDA 요약을 계산식으로 대조한다.
- 실제 모델은 돌리지 않는다. 관련 단위 테스트, YAML 파싱, compile, diff 정적 검사만 수행한다.

## 점검 순서

- [x] 1차 감사 결정 D-33~D-38과 현재 작업 트리 범위를 확인한다.
- [x] 3a의 파일 수·행 수·채널 수·비율·topk 계산을 manifest와 EDA 요약에 맞춰 재계산한다.
- [x] 입력 지문 → loader → 비율·validation 분할 → 세션 window → 학습 → `L-W` 점수 정렬을 추적한다.
- [x] 정규화 → smoothing → max 집계 → 파일명·metadata → 완전성 판정까지 추적한다.
- [x] GHL back-trim·−TOPK·topk 민감도와 HAI 다중 세션·그래프 저장 경로를 추적한다.
- [x] 재현된 결함을 테스트 우선으로 최소 수정한다.
- [x] 전체 단위 테스트와 정적 검사를 한 번 수행하고 D-39 및 진입 점검표를 갱신한다.

## 완료 조건

2차 감사에서 발견한 결함과 수정 근거가 코드·테스트·`DECISIONS.md`에 서로 같은 뜻으로 남아야 한다. 결함이 없는 항목은 수정하지 않고 확인 근거만 기록한다. 3b는 여전히 실행 전 정적 준비 상태이며, commit·clean 작업 트리에서 합성 dry-run을 다시 통과하기 전에는 4단계로 넘어가지 않는다.
