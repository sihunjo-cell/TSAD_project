# 3단계 3차 논리 감사 실행 계획

> 현재 누적 작업공간에서 직접 수행한다. 기존 변경을 옮기거나 커밋하지 않으며, 실제 GHL·HAI 학습과 합성 모델 실행은 하지 않는다.

## 목표

4단계에 들어가기 전 3a의 데이터 결정과 3b의 실행 경로를 다시 대조한다. 앞선 감사에서 놓친 결함만 재현해 최소 수정하고, 이미 닫힌 결론은 근거 없이 흔들지 않는다.

## 감사 순서

### 1. 봉인 범위 확인

- 3a·3b 완료 범위와 4단계 금지선을 위 문서끼리 대조한다.
- 현재 작업트리와 실험 산출물 유무를 읽기 전용으로 확인한다.
- 대형 원본 파일 전체 읽기와 SHA-256 재계산은 하지 않는다.

### 2. 결정값 역추적

- 데이터셋별 비율, 시계열·채널 수, split, seed, `topk`, window, smoothing, 정규화 순서를 설정·코드·테스트·문서에서 역추적한다.
- 숫자 하나마다 원천 근거와 소비 지점이 맞는지 확인한다.
- 이미 검증된 원본 레포 줄 번호는 기록의 일치 여부만 확인한다.

### 3. 실행 경계 감사

- 입력 검증 → split → 학습 → 예측 → 점수 저장 → HAI 인접행렬 → 완료 표식 순서를 정상·실패·재실행 경로로 나눠 읽는다.
- CPU와 CUDA의 장치 이동, 중단 뒤 재개, 이전 설정으로 만든 산출물의 오인 가능성을 따로 점검한다.
- 현재 데이터 계약으로 닿지 않는 방어 코드보다 실제 결과를 바꿀 수 있는 결함을 우선한다.

### 4. 결함 수정

- 재현되는 결함이 있을 때만 실패 테스트를 먼저 추가한다.
- 원인을 고치는 최소 diff만 적용한다. 추측성 추상화와 새 의존성은 넣지 않는다.
- 결함이 없으면 코드 변경 없이 감사 결과만 남긴다.

### 5. 검증과 기록

- 고정 환경에서 관련 테스트, 전체 테스트, YAML 파싱, `compileall`, 설정별 실험 수 계산을 실행한다.
- 변경 diff와 작업트리에서 새 실험 산출물이 생기지 않았는지 확인한다.
- 새 결정이나 정정이 생기면 `DECISIONS.md`에 D-40으로 기록하고, 재개 문서와 설계 문서도 같은 문장으로 맞춘다.
- 사용자 검토 전 커밋하지 않으며 4단계로 넘어가지 않는다.

## 완료 조건

- 새 결함은 실패 테스트와 수정 후 통과 증거가 함께 남는다.
- 새 결함이 없으면 확인 범위와 실행한 검증을 문서에 남긴다.
- 완료 보고에 현재 끝난 단계, 근거 파일, 원본 레포 경로·줄 번호, 실행하지 않은 항목을 적는다.

## 수행 결과

- 3a의 수치와 비율 역할은 유지했다. GHL은 25개·19채널·학습 길이 39,938~50,000, HAI는 86채널·훈련 4세션·테스트 2세션이다. `topk` 계산 5·22와 실험 조합 `375·225·150·450·20`도 YAML과 봉인 로그가 일치했다.
- 재개 판정 결함 하나를 재현했다. 이전 TSAD commit의 snapshot과 `COMPLETE`가 남아 있으면 현 실행의 완료분으로 건너뛰던 문제다. 배치가 두 저장소의 clean 상태와 hash를 한 번 확인하고, snapshot의 두 hash가 그 값과 같을 때만 완료로 세도록 고쳤다.
- 완료 검사 CLI와 HAI Jaccard 집계도 같은 실행 신원을 확인한다. Jaccard는 현재 commit의 HAI 20개 조합이 모두 끝나기 전에는 산출물을 쓰지 않는다.
- TopK는 대각선을 미리 가리지 않지만 cosine 동률에서 self-edge가 반드시 뽑힌다고 보장할 수 없다. “항상 k−1개 + 자기 1개”라는 문장을 고치고 실제 추출 edge에서 self-edge를 제거한다는 계약으로 맞췄다.
- 고정 Lightning 2.6.2의 `prediction_loop.py:273-274`가 예측을 CPU로 옮겨 보관함을 확인했다. CUDA 예측과 CPU 정답의 장치 불일치 의혹은 성립하지 않아 러너는 바꾸지 않았다.
- 실패 테스트 두 건을 먼저 확인했고 완료 신원·Jaccard 회귀 테스트를 더해 전체 단위 테스트 99건이 통과했다. YAML 5개·환경 12항목·조합 수를 확인했고 `compileall`과 `git diff --check`도 통과했다. 실제 GHL·HAI·합성 모델은 실행하지 않았고, 원본 CSV와 SHA-256도 다시 읽지 않았다.
