# C(주혜) — 실행·통계

지금 짤 것과 기다릴 것을 나누는 게 핵심입니다. 근거는 계획서 8절·3-3과 D-18입니다.

## 1부. 제가 당장 필요한 것 (필수 — 데이터 없이 지금 만들 수 있는 것들)

지금 짤 수 있는 것은 데이터가 필요 없는 통계 도구들입니다. 대응 Wilcoxon(Bonferroni 보정 α*=0.01), TOST(±δ 단측 2회, 판정은 2×2 표로), 그리고 지속 초과 판정기 — 판정기의 단위 테스트 기대값은 계획서 3-3의 수치 예를 그대로 쓰시면 됩니다. D=(+0.021,−0.008,+0.030,+0.041,+0.052)에서 c*=20%가 나와야 합니다. 중도절단 처리(전 비율이 양수면 5%를 관측 하한으로 표기)와 "교차점 없음" 처리도 포함해 주세요. bootstrap은 B=10,000입니다.

Jaccard 집계기도 지금 만들 수 있습니다. 제가 exp03에서 self-edge를 제거하기 전/후의 edge 집합을 넘깁니다(extract_best_adjacency 산출물). seed 10개가 만드는 45쌍 전부의 Jaccard를 계산해 중앙값·사분위·범위로 보고하는 집계기입니다(D-18).

기다릴 것은 exp02 배치입니다. 35~50 GPU-시간짜리라 Manifest 봉인과 저의 실데이터 스모크 통과가 먼저입니다. 그때까지는 로그 자동기록 틀만 잡아 두시면 됩니다.

## 2부. 이후에 하면 좋은 것 (부차 — 결과가 오기 전에 틀을 세워두는 일)

1부의 스크립트 3종이 테스트를 통과한 뒤 얘기입니다. 공통 원칙은 하나 — 결과가 도착한 날 분석이 바로 돌게, 틀을 결과보다 먼저 완성해 두는 겁니다. 항목마다 쓰일 곳을 붙였습니다.

### ① δ 산출 절차 → 등가성 검정의 골대(8절, 사전 등록 3종)

- δ는 계층1의 결정적 방법들(z-score·L2·PCA·KNN·MatrixProfile)이 시계열이 바뀔 때 보이는 산포로 사전 고정합니다. 논거는 계획서의 한 문장 그대로입니다 — 결정적 방법조차 이만큼 흔들리니 그보다 작은 차이는 구분할 실익이 없다.
- 사전 등록 항목이라 결과를 본 뒤에는 못 정합니다. 지우님의 계층1 점수가 나오는 즉시 계산되도록 스크립트를 미리 만들어 두면, 점수 도착일에 δ가 잠깁니다.

### ② 로그 자동기록 틀 구체화 → 5-4·5-5의 저장 규율

- 실행당 설정·seed·커밋 해시·학습/추론 시간을 자동으로 남기는 틀. 결과표에 시간 열을 병기하는 것까지가 한 세트입니다 — 배치 의사결정에서는 성능만큼 비용이 중요하다는 게 계획서 문장입니다.
- 제 러너는 이미 스냅샷(config + 두 저장소 git hash)과 early stopping 로그를 남기니, 그 JSON 형식을 그대로 읽는 쪽으로 맞추면 이중 작업이 없습니다.

### ③ 그림·표 틀 선제작 → 최종 결과물 1·2번

- 3층 곡선 그림(준수평선 + 우상향선 + 수평선)과 교차점 분포 표(중앙값·사분위 + "교차점 없음" 비율 열)를 합성 난수 점수로 미리 그려서 형식을 확정해 두는 겁니다. 실데이터가 오면 숫자만 갈아 끼우면 됩니다.
- 대응 쌍 규칙도 이 틀에 미리 박아 두세요: 비율마다 (GDN − PCA)와 (GDN − MOMENT_ZS)를 같은 시계열 위에서 계산하고, GDN 값은 seed 3회의 중앙값입니다(3-3·8절).
- "없음"을 큰 수로 바꿔 평균 내지 않는다는 3-3의 경계 처리가 표 형식에 그대로 드러나야 합니다.
- 회수 분석 표(구간 × 모델 × 비율)의 해석 틀도 여기 포함입니다 — 원표와 히트 판정은 지우님 판정기에서 오고, 10% 교차 해석이 주혜님 몫입니다(8절 보조 분석).

### ④ 통계 요약의 해석 한계 자동 명기 → 3-3·8절

- Wilcoxon·TOST·B=10,000 bootstrap은 모두 GHL 25개 task 안에서만 해석합니다. 같은 시뮬레이터 산물 사이의 독립성을 보장할 근거가 없으므로 p값·등가 판정·신뢰구간을 제조 공정 모집단으로 일반화하지 않는다는 한계(R1)를 결과물에 자동으로 붙여 주세요. 손으로 옮기다 빠뜨리지 않게 스크립트가 소유하는 편이 안전합니다.
