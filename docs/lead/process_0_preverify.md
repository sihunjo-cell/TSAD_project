# 사전 점검 결과

이 문서는 실험 전에 확인한 문제와 현재 조치만 모은다. 조사 과정과 일회성 진단 코드는
보존하지 않는다.

## 현재 상태

저는 계층 1·2·3 모델과 점수 산출을 맡는다. 계층 2의 GDN만 실행 직전까지 준비됐으며
실데이터 학습은 아직 하지 않았다. GHL·HAI의 파일 구조와 학습 비율은 실물 데이터로 먼저
확인했다. 강혁의 최종 검토가 현재 판단을 바꾸면 영향받는 부분만 다시 계산한다.

지우의 채점기와 ℓ_max, 주혜의 난이도·통계 코드는 대신 만들지 않았다.

## 확인한 문제와 조치

| 점검 대상 | 확인한 내용 | 현재 조치 |
| --- | --- | --- |
| GDN 입력 | GraGOD의 `reshape`가 batch와 node 축의 값 순서를 섞었다. | 해당 두 줄을 `permute`로 고치고 수정본을 GDN 코드 옆에 뒀다. |
| 점수 후처리 | GraGOD smoothing이 feature 축에 작용하고 마지막 점수를 버렸다. | 후행 4칸 smoothing과 `L-W` 정렬을 이 프로젝트에서 처리한다. |
| 분할과 정규화 | 학습 비율과 validation 적용 순서가 불명확했다. | 원 학습 구간의 앞쪽 비율을 남기고 그 안의 마지막 20%를 validation으로 쓴다. 테스트는 자르지 않는다. |
| 비율별 데이터 감사 | 과거 누적 구간을 전체 학습 구간의 통계와 비교해 이후 관측치가 기준에 들어갔다. | 전체 구간과의 대표성 계산과 해당 CSV 생성을 없앴다. 각 누적 구간 안의 표본 수·채널 변화·분산만 검사한다. |
| GHL 입력 | 25개 시계열의 학습 길이는 39,938·43,750·50,000이고 센서는 19개다. | 5·10·20·50·100%를 최저 데이터, 저데이터, 중간, 고데이터, 전체 기준 조건으로 쓴다. 관계 구조 회복이나 최적 비율로 해석하지 않는다. |
| HAI 입력 | HAI 23.05는 훈련 4세션, 테스트 2세션, 센서 86개다. | 파일 경계를 보존하고 train1→test1, train1+train2→test2를 쓴다. `topk=22`는 회의 전 잠정값이다. |
| GDN 설정 | 구현마다 기본값이 달랐다. | 현재 YAML 값은 합성 검증용 잠정값이다. 재현 기준·train stride·topk를 본 실험 전에 확정한다. |
| 실행 흐름 | snapshot부터 점수 저장까지 실제 호출 형태를 확인할 필요가 있었다. | 합성 입력으로 checkpoint, 점수 8벌, metadata와 완료 검사를 확인했다. |

GHL 5% 구간에서는 475개 채널-시계열 조합 중 완전히 고정된 조합이 154개였고 IQR이 0인
조합은 279개였다. 5%는 충분한 학습량이 아니라 모델이 무너지는 경계를 보는 조건이다.

HAI의 이전 10%·4세션 감사값은 현재 시간 조건 설계의 입력으로 쓰지 않는다. 움직이지 않은
채널을 삭제하지 않는 원칙은 유지한다.

## 남긴 것

반복할 가치가 있는 데이터 감사와 합성 dry-run만 `tests/checks/`에 남겼다. 점검 결과는
`experiments/checks/`, GraGOD 입력 축 수정은
`src/models/tier2/gdn/gragod_input_transform.diff`에서 관리한다. GHL 실행 결과는
`experiments/01_ghl_main/`, HAI 실행 결과는 `experiments/02_hai_extension/`에 저장된다.

GHL·HAI 데이터 감사는 수정한 코드로 다시 실행해 로그와 snapshot을 갱신했다. 전체 구간을
기준으로 삼던 대표성 CSV는 제거했으며, 현재 잠정 GDN window 5만 검사한다.

문제를 찾는 데만 쓴 진단 코드와 중복 검증 문서는 삭제했다.

## 실데이터 실행 전 조건

실데이터 학습은 아래 조건이 모두 정리된 뒤 시작한다.

1. 강혁이 Manifest를 확인하고 채널별 주기성 표를 지우에게 넘긴다.
2. 지우가 점수 파서, ℓ_max, threshold 250개와 무작위·point-adjust 검증을 확정한다.
3. 주혜가 난이도·hit 판정과 통계 절차를 확정한다.
4. 제가 계층 1의 6종, 계층 2의 AE·LSTMAD·USAD, 계층 3의 MOMENT_ZS·Chronos를 같은 점수 계약으로 구현한다.
5. 연구실 서버 환경과 고정된 소스 버전을 확인하고 합성 dry-run을 한 번 통과한다.

다음 작업은 실데이터 실행이 아니다. `next_session.md`에 적힌 모델 구현 준비부터 이어간다.
